## x87 reachability proof

A deterministic source trace with
`rg -n 'X64_OP_X87|x87_(mem|op0)' src/cg/x86_64` inspected every x87 opcode
definition, emission case, verifier rule, and construction site. `emit.c` only
translates already-selected `X64_OP_X87_*` MIR. Every ordinary constructor in
`isel.c` is dominated by an `IRT_F80` source/result/ABI gate, or by a
conversion whose source or destination is `IRT_F80`; `x87_trunc_store` is only
called from the `st == IRT_F80` conversion arm. Thus no ordinary f32/f64 IR
path constructs x87 MIR. The separate GNU inline-assembly path requires an
explicit `t`/`u` x87 constraint (`ASM_CLS_X87`/`ASM_CLS_X87UP`), so it is a
source-text x87 license rather than accidental backend selection.

The source trace was paired with executable positive and negative probes at
every supported non-fast optimization level. The f32/f64-only probe executed
successfully and its assembly contained zero whitelisted x87 mnemonics; the
otherwise matched long-double probe executed successfully and contained x87:

| Level | f32/f64 runtime | f32/f64 x87 count | long-double runtime | long-double x87 count |
| --- | --- | ---: | --- | ---: |
| O0 | PASS | 0 | PASS | 38 |
| O1 | PASS | 0 | PASS | 35 |
| O2 | PASS | 0 | PASS | 29 |
| O3 | PASS | 0 | PASS | 29 |
| Os | PASS | 0 | PASS | 29 |

Together with the 20-operation `x64_f80_chain_balance` pipeline test, this
proves both halves of the reachability claim: ordinary float/double code does
not reach x87, while long double does and remains locally stack-balanced.
