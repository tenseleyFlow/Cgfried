# arm64-linux corpus debt under CGF_SPILL_ALL=1.
#
# Forcing every interval to memory is the only thing that exercises the spill
# rewrite broadly, and that rewrite is where an instruction's index moves --
# the exact shape of the NZCV bug fixed in `9c98698`, which one fixture at
# one optimization level was all that caught. The ordinary lane runs at
# natural pressure, where a handful of corpus programs spill at all.
#
# Enforced EXACTLY in both directions by scripts/a64_corpus_lane.sh, the same
# as the ordinary ledger: a new failure fails the lane and so does an entry
# that starts passing. Run it with
#
#     CGF_A64_SPILL_ALL=1 CGF_A64_CORPUS_WORK=build/a64-corpus-sa \
#       CGF_A64_LEDGER=ci/expected_a64_spill_all_failures.txt \
#       sh scripts/a64_corpus_lane.sh
#
# or `make test-a64-spill-all`.
#
# TWO clusters, both UNDIAGNOSED. They are recorded as OBSERVATIONS, because
# naming a cause I have not seen in a disassembly is how the last two wrong
# diagnoses started.
#
# 1. Floating point produces WRONG ANSWERS or faults. printf_fp prints
#    pi=3.140625 for 3.141593, which is a value that lost mantissa bits
#    somewhere, not a marshalling mistake -- the reload/consume pairing at
#    the call is correct on inspection.
#
# 2. Two integer programs fault or answer wrongly, and varargs_sum computes
#    a wrong sum.
#
# The third cluster, frame immediates, is CLOSED: stp/ldp pre/post-index and
# scaled offsets share a signed 7-bit field scaled by 8, so the bound is +504
# and not 512 (legal for the prologue's store, illegal for the epilogue's
# matching load), and a frame object past 4095 now takes two ADDs the way the
# stack adjustment always has. That fix removed three entries from this list
# and unpinned int/big_frame from the ordinary ledger.
#
# Format: <suite>/<name> [-O<level>] # <cause or observation>

fp/float_conv [-O0] # FP under spill: exit 5, undiagnosed
fp/fp_call_args [-O0] # FP under spill: exit 1, undiagnosed
fp/printf_fp [-O0] # FP under spill: prints pi=3.140625, undiagnosed
fp/u64_double [-O0] # FP under spill: exit 1, undiagnosed
fp/varargs_mixed [-O0] # FP under spill: SIGSEGV, undiagnosed
int/bsearch_hand [-O0] # exit 1, undiagnosed
int/switch_dense [-O0] # SIGSEGV, undiagnosed
int/varargs_sum [-O0] # wrong sum, undiagnosed
